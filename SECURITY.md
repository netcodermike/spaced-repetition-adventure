# Security and privacy

These are educational first releases, not independently audited software. Read the project-specific limitations in README.md before trusting important data or exposing a listener remotely.

Use synthetic inputs for development. Keep backup keys, tokens, location markers, notes, and screenshot contents out of source control and public issues. Runtime data is local unless you explicitly send it to a configured backup endpoint or export/share it. The project makes no automatic cloud connections for analytics.

Report non-sensitive bugs through repository issues. For a vulnerability that would expose data, use GitHub's private vulnerability reporting if enabled; otherwise contact the maintainer through a privately agreed channel before publishing exploit details. No response-time or support guarantee is implied. Do not test against other people's systems.
